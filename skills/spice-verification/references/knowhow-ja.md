# 過渡 SPICE 検証のノウハウ

## 完走と仕様適合を分ける

終了コード 0 でも、ログに `timestep too small` が残っていたり、RAW が停止時刻に到達していなければ未完走です。KiCadMCP の実行結果と、事前仕様の停止時刻を両方確認します。ソルバー設定を緩めて通った場合は変更を記録し、同じモデルと刺激で波形・電荷・イベント時刻が安定するか比較します。モデルの効果を除いて数値計算を通した場合、その効果についての仕様適合とは扱いません。

要件の成功ケースに加え、保護を働かせない条件や不適切な復帰条件など、期待する失敗を観測する負例を用意します。負例で再送電を観測できることは検査の感度を示しますが、保護成功件数には加えません。

LTspice の macOS / Wine 構成では、子プロセスが独立セッションへ移り、実行器の process group 終了後も残る場合があります。タイムアウト後は、その実行で起動したと確認できる PID と開始時刻・実行先を確認し、所有するプロセスだけを終了します。共有の `wineserver` や他の LTspice 実行を一括終了しません。残存プロセスの有無と、後から RAW / log が更新されていないかも記録します。

## 再送電・戻り電流の測定

電流矢印を「電源 → 負荷」の正方向として図と仕様に明示します。SPICE 電圧源の枝電流は想定と符号が逆になることがあるため、既知の抵抗負荷で確認します。入力コンデンサの充電電流、スイッチ出力電流、実際の負荷入力電流を別々に保存します。一つの枝電流を全経路の電流と読み替えません。

異常検出時刻と実際の送電許可信号の LOW 時刻を記録し、少なくとも次の二つを別の窓で測ります。

- 遮断直後: ピーク、正方向電荷、閾値超過時間。容量や制御遅延による短い残留電流を確認します。
- 過渡後: 明示した待ち時間以降のピーク、時間重み平均、正方向電荷。継続的な再送電の有無を判定します。

符号付き積分だけでは、逆向きの電流と相殺してしまいます。正方向電荷はゼロ交差を分割して積分します。適応時間刻みの単純なサンプル平均は、細かい刻みが集中する過渡区間に偏るため使用しません。閾値と判定窓は実行前に決め、グラフを見て都合よく変更しません。適用する設計上の許容値が未定なら、測定結果と未判定を明示します。

グラフは共有の時間軸で、電源電圧、戻り電源、送電許可信号、負荷へ流れる正方向電流を並べます。全期間に加え遮断直後の拡大図を載せ、凡例に枝名と正方向、単位、異常時刻、判定窓、使用モデルを記します。測定 CSV / RAW、数値 JSON、デッキとモデルのハッシュを残し、図だけを根拠にしません。

## コーナーと半刻み比較

全組み合わせを無制限に増やすより、設計上の境界を優先します。電圧の上下限、弱い電源の内部抵抗、電源が回復する時刻、負荷容量と ESR、負荷急変、保護のしきい値公差、検出・遮断遅延を必要に応じて組み合わせます。複数の独立電源がある場合は、一方だけ抜去した条件、両方を抜去した条件、制御電源が失われた条件を分けます。

臨界ケースは最大時間刻みを半分にして再実行します。`.tran` の出力間隔と最大刻みは別の引数であるため、実際に最大刻みが変わったことをデッキで確認します。電荷やピークなど、結論に使う全指標へ絶対許容差と相対許容差を事前指定します。刻みを半分にしても、モデルが省略した逆流コンパレータ、PWM、熱、ヒューズ動作が検証されたことにはなりません。保存点間より短いパルスは未観測です。

## 実際の C 制御 core を使う因果的な再生

平均回路に理想化した「正解の遮断波形」を直接与えると、制御ソフトの不具合を検査できません。実ファームウェアと同じ制御 core をホスト用 adapter に接続し、ADC / GPIO / IRQ の入力と出力を次の順で記録します。

1. 時刻付きの物理刺激とモデルの観測信号を生成し、ADC のサンプリング周期、量子化、検出遅延、割り込み極性を定義します。
2. 観測時刻までに得られた情報だけを C core に渡します。将来の電圧回復や正解の遮断時刻を入力しません。同時イベントの優先順位は実ファームウェアに合わせます。
3. core の実出力を PWL 等へ変換し、回路を再実行します。出力により入力観測が変わる場合は、再観測してイベントが安定するまで反復するか、相互接続可能な連成器を使います。反復回数の上限を決め、不一致は未完了として残します。
4. core と adapter のソースハッシュ、コンパイラ条件、初期状態、刺激、入力イベント、出力イベント、反復差分を保存します。RAM 状態と不揮発状態を混同せず、制御電源の消失・再起動・破損記録も別ケースにします。

再生で検査できる範囲は adapter がモデル化した入力までです。GPIO レベル、実割り込み、ADC 取得エラー、不揮発書き込み、物理的な遮断遅延については、別の adapter テストや実機測定が必要です。この手法の汎用手順を共有し、案件固有のファームウェアや実測波形を本リポジトリへ持ち込みません。

## モデルと共有の境界

平均モデルは動作モードやエネルギーの概算に有用ですが、省略した逆流・PWM・熱・短絡保護を保証できません。メーカー詳細モデルが別エンジン専用、暗号化、収束不良の場合は、失敗ログと適用範囲を残します。独立モデルでの成功に置き換えて「メーカー検証済み」と記載しません。

公開するのは再利用できる検査器、合成回路、匿名化した手順です。モデルの再配布条件は提供元で確認し、キー、利用者のファイルパス、私用 CAD、個別案件のログや波形を公開しません。シミュレーション結果から製造可否や実機の安全性を自動承認しません。
